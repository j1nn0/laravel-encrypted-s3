# ADR 0003: Object location does not build the delegated adapter

`Support\ObjectLocation` exposes `root()` as a raw string (`src/Support/ObjectLocation.php:28-31`) so that `EncryptedS3DiskFactory` can hand it to the delegated `AwsS3V3Adapter` (`src/EncryptedS3DiskFactory.php:33,38`), which builds a second `PathPrefixer` of its own; `ObjectLocation` keeps a separate one for encrypted keys (`src/Support/ObjectLocation.php:14,20`). Moving the delegated adapter's construction into `ObjectLocation` would give the prefix one owner and make drift between the crypto path and the delegated path structurally impossible, but it would also make a value object that only names keys depend on `League\Flysystem\AwsS3V3\AwsS3V3Adapter`, `Aws\S3\S3Client`, the visibility converter, and the MIME type detector — the whole delegated half of the split point would be assembled by the module with the narrowest job. The drift it would prevent has not occurred and is covered by `test_root_prefix_is_used_consistently_for_encrypted_and_delegated_operations` (`tests/Feature/EncryptedS3FilesystemTest.php:462`), so the two prefixers stay and `root()` stays on the interface. Revisit only if that test starts catching real divergence, or if a third consumer of the root appears.
